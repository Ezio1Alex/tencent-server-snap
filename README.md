# 腾讯云轻量服务器秒杀抢购脚本

一个**开箱即用**的腾讯云活动页自动化抢购工具。用脚本替代你手动刷新和点击下单：扫码登录一次，脚本自动同步服务器时间、卡准放货瞬间、高频并发下单。

> ⚠️ 本工具仅用于个人学习研究。抢购行为与账号风险请自行评估，勿用于商业用途。

## 它能做什么

| 能力 | 说明 |
|---|---|
| 一键运行 | 双击一个文件，扫码登录后全自动跑到抢购完成 |
| 凭证自动捕获 | 登录时自动保存 Cookie 和 CSRF Token，不需要手动复制 |
| 服务器时间对齐 | 以腾讯云服务器时间为准，不依赖电脑本地时钟 |
| 毫秒级卡点 | 秒杀前校准时间偏移，提前 0.01 秒开火，把请求打在放货瞬间 |
| 高频抢购 | 放货后 3 秒内 14 路独立请求通道持续下单，抢到即停 |
| 全天候值守 | 错过 10:00 自动接着等 15:00，不用重新启动 |

## 抢购流程一览

整个脚本按这个时间轴运行：

```
距开抢 15 秒以上     →  每 3 秒轮询一次服务器时间
距开抢 15 秒以内     →  校准毫秒级时间偏移（多次采样），50ms 粒度卡点
距开抢 0.01 秒       →  提前开火，进入高频抢购窗口
放货瞬间            →  14 路独立请求通道持续下单，抢到即停
抢到 code=0         →  ✅ 停止并退出
窗口结束未抢到       →  ❌ 自动等待下一场
```

关键策略：**提前开火**。早到的请求会被服务器无害地拒绝（返回「秒杀尚未开始」），而恰好跨过放货边界的请求才是真正抢到库存的子弹。

## 地域对照表

活动接口里的 `region_id` 对应地域：

| region_id | 地域 |
|---|---|
| 1 | 广州 |
| 4 | 上海 |
| 8 | 北京 |

默认抢购 `[1, 4]`（广州、上海）。想要包含北京，把配置里的 `REGION_IDS` 改成 `[1, 4, 8]` 即可。

## 抢购参数速查

编辑 `snap_up_server.py` 顶部的「抢购配置」区：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `SECKILL_HOURS` | `[10, 15]` | 每天抢购时刻（北京时间） |
| `REGION_IDS` | `[1, 4]` | 目标地域：1=广州，4=上海，8=北京 |
| `RUSH_DURATION` | `3` | 抢购爆发窗口（秒），窗口内持续下单 |
| `RUSH_CONCURRENCY` | `14` | 独立请求通道数（每路一个线程，各自发单），调大更猛但易被限流 |
| `REQUEST_TIMEOUT` | `30` | 单个请求等待响应上限（秒），秒杀高峰响应延迟，给足时间 |
| `RUSH_LEAD` | `0.01` | 提前开火时间（秒），几乎贴着放货瞬间 |

## 开始之前：准备环境

### 1. 安装 Python

去官网下载安装包：**https://www.python.org/downloads/**

- 点击黄色大大的「Download Python 3.x.x」按钮
- 安装时 **务必勾选最下方的 `Add Python to PATH`**（否则后面命令行会找不到 python）
- 装完后验证：打开命令行（`Win + R` 输入 `cmd` 回车），输入：

```bash
python --version
```

能看到类似 `Python 3.11.x` 就说明装好了。

### 2. 获取本项目的代码

方式一（推荐）：打开命令行，执行

```bash
git clone https://github.com/Ezio1Alex/tencent-server-snap.git
```

方式二：进入 GitHub 项目页面 → 点绿色的 `Code` 按钮 → `Download ZIP` → 解压到任意目录。

### 3. 安装项目依赖

在命令行里进入项目目录（把路径换成你解压/克隆的位置）：

```bash
cd 项目所在目录
pip install -r requirements.txt
```

然后安装 Playwright 需要的浏览器内核（一条命令，下载几十 MB）：

```bash
playwright install chromium
```

## 完整上手步骤（跟着做就行）

### 第 1 步：改配置（只需要改一次）

用记事本打开 **`snap_up_server.py`**，看到文件最上方有几行大写字母的配置。默认值对应某一个具体活动，**可能已经过期**。请按本 README 第 6 节「如何配置你自己的活动」的方法，把参数改成你自己活动页的值。

> 如果你只想先跑通流程、不想配活动，可以跳过这步，直接用默认值跑起来看效果（但到点未必能下单成功）。

### 第 2 步：双击启动

双击项目目录里的 **`start.bat`**。会自动弹出浏览器并显示腾讯云登录二维码。

### 第 3 步：扫码登录

用手机上的**腾讯云 App / 微信**扫码，在手机上确认登录。登录成功后：

- 浏览器会自动跳回活动页，然后**自动关闭**
- 目录下自动生成 `cookies.json` 和 `csrf_token.txt` 两个文件（这是你的登录凭证，**不要发给任何人，不要提交到 Git**）

### 第 4 步：等待

抢购脚本自动接管命令行窗口，开始同步服务器时间、显示倒计时：

```
🚀 启动腾讯云抢购脚本...
⏳ 距下一场秒杀（2026-08-12 10:00 北京时间）还有 16小时50分13秒，当前服务器时间: 1786439387000
⏳ 距下一场秒杀（2026-08-12 10:00 北京时间）还有 16小时50分9秒，...
```

**不要关闭这个窗口**。脚本会一直挂着，直到秒杀时刻。

### 第 5 步：到点自动开抢

到了配置的秒杀时刻，脚本自动进入高频抢购窗口，命令行开始刷「⚡ 第N轮抢购」和「🎯 核心购买接口返回」，期间不需要你做任何事。

## 如何配置你自己的活动

每个腾讯云活动都有自己的一组参数，脚本里默认的数值**只适用于特定的那场活动**。换活动或活动更新后，需要重新抓取。方法如下：

### 1. 打开浏览器抓包

1. 用 Chrome / Edge 打开你的腾讯云活动页，**并登录**
2. 按 `F12` 打开开发者工具，切到 **Network（网络）** 标签
3. 在页面上随便点一下「立即购买」或刷新页面，让页面发起请求
4. 在请求列表顶部的筛选框输入 `dianshi`，过滤出接口请求

### 2. 找到参数

点击请求名带 **`check-available`** 或 **`do-goods`** 的那一条，在 **Payload（负载）/ Request Body（请求体）** 里找到：

| 配置项 | 从哪里找 |
|---|---|
| `ACTIVITY_ID` | 请求体里的 `activity_id` |
| `CHECK_ACT_ID` | `check-available` 请求体里 `goods[0].act_id` |
| `DO_ACT_ID` | `do-goods` 请求体里 `goods[0].act_id` |
| `BUSINESS_ID` | `do-goods` 请求体里 `business.id` |
| `GOODS_TYPE` | `do-goods` 请求体里 `goods[0].type`（如 `bundle_budget_mc_lg4_01`） |
| `IMAGE_ID` | `do-goods` 请求体里 `goods[0].goods_param.imageId` |
| `BLUEPRINT_ID` | `goods[0].goods_param.BlueprintId` |
| `TIME_SPAN_UNIT` | `goods[0].goods_param.timeSpanUnit`（购买时长，如 `12m`） |
| `ACTIVITY_URL` | 浏览器地址栏的活动页地址 |

### 3. 填回配置

把抓到的值填到 `snap_up_server.py` 顶部的配置区，保存即可。

> **为什么一定要重新登录再抓包？** 因为 CSRF Token 绑定登录会话，每次登录都会变。脚本的登录步骤会自动捕获最新 token，只要在秒杀前重新跑一次登录（第 2~3 步），凭证就一定是新的。

## 抢购过程中你会看到什么

| 输出 | 含义 |
|---|---|
| `⏳ 距下一场秒杀…` | 正常运行，等待中 |
| `🎯 进入最后15秒，校准毫秒级服务器时间...` | 进入最后的精准卡点阶段 |
| `⚡ 第N轮抢购 ...` | 第 N 轮下单开始 |
| `🎯 核心购买接口返回：{...}` | 服务器对下单请求的原始响应 |
| 响应 `code: 0` | 下单成功，脚本打印 `🎉 抢购成功` 并退出 |
| 响应 `1101001 秒杀尚未开始` | 还没到放货时刻（提前开火的正常现象） |
| `❌ 抢购窗口结束（5秒），未抢到` | 本场没抢到，自动等下一场 |

## 常见问题

**Q：双击 start.bat 后没有弹出浏览器？**
A：确认 `playwright install chromium` 执行成功。也可以在命令行手动运行 `python get_cookies.py` 看报错信息。

**Q：扫码登录后卡住不动 / 一直显示等待？**
A：活动页地址每月更换，`get_cookies.py` 里的 `ACTIVITY_URL` 可能已过期。把它改成浏览器地址栏当前的活动页地址再运行。

**Q：抢购时报「CSRF 校验失败」？**
A：`cookies.json` 和 `csrf_token.txt` 不是同一次登录产生的。重新运行 `start.bat`（或 `get_cookies.py`）完整登录一遍即可。

**Q：一直提示「秒杀尚未开始」？**
A：确认当前时间已临近配置里的 `SECKILL_HOURS` 时刻。脚本在开火窗口内会持续下单，等到放货瞬间自然有响应。

**Q：抢购时提示「Read timed out 请求超时」？**
A：秒杀高峰服务器被挤爆，部分请求卡住超时是正常现象。下单超时已设为 30 秒，给足时间让踩中时刻的请求等到结果。若想调大，把 `REQUEST_TIMEOUT` 调大（注意会相应减少总请求数）。

**Q：下单返回权限类错误？**
A：账号未实名认证，或该商品未对你的账号开放。先在活动页手动下一单确认账号状态。

**Q：想更激进地抢，怎么调？**
A：`snap_up_server.py` 配置区：`RUSH_CONCURRENCY` 调大（如 20）、`RUSH_DURATION` 调大（如 5）。注意过高的频率可能触发风控。
